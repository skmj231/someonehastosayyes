Approval infrastructure for n8n, Make, Zapier & agents

The safety gate before automation becomes action.

Before your automation sends, spends, deletes, refunds, or deploys—someone has to say yes. One API pauses the workflow, asks in Slack, email, or a private link, then returns one signed decision.

    Make: one scenario asks, one continues.

    Guided setup · about 10 min

    The tested setup uses one short scenario to ask and another to receive the answer. The asking scenario ends immediately, so it does not stay running while a person decides.

    Receiverapproval requestrun once
    1. Create the receiving scenario firstAdd Webhooks → Custom webhook and copy the URL Make gives you.
    2. Add one HTTP request to your existing scenarioPaste the endpoint, your API key, and the receiving webhook URL using the values below.
    3. Run once, decide, then turn the receiver onMake learns the decision fields. Continue when approved is true.

    Zapier: one Zap asks, one receives.

    Webhook setup · paid Zapier plan

    This uses Webhooks by Zapier, not a native someonehastosayyes app. The guide is tested, but Zapier describes webhooks as an advanced feature.

    Catch HookCustom Requestpublish both
    1. Build the receiving Zap firstChoose Webhooks by Zapier → Catch Hook and copy its unique URL.
    2. Add a Custom Request to the Zap that needs approvalUse the Catch Hook URL as callback_url.
    3. Test the decision and publish both ZapsUse the returned approved field in your next action or Filter.

    Before you start: Webhooks by Zapier is not available on the Free plan. Your API key is entered in the Zap step, so limit editor access to people you trust.
